二、闪烁判据第二次误报 —— 而且两个 bug 叠在一起

v1.27 的判据（switches >= 3）本局触发 2 次，窗口逐字是：

[3D2ED0A433B46771 96.6] [AEAB5E65C0210DFE 96.6] [6AD5178233020383 43.0] x6
[6AD5178233020383 43.0] x4 [5F9EB3FEDCEF8383 63.8] x3 [7DDF048D32FCE9A5 73.4]

两条都是单向亮度渐变（加载屏由亮转暗 / 由暗渐亮），一次回返都没有， 而且都发生在世界进入前后。

bug 1 · 环形缓冲被当成普通数组扫描。 样本写在 pixelProbeRingHash[pixelProbeRingAt]，槽位顺序 = 写入顺序被 ringAt 旋转过。 distinct 侥幸没坏（与顺序无关），switches/maxRun 全错。
铁证：#21 打出 sw=3 maxRun=5，而该窗口尾部是 6 个完全相同的样本 ⇒ maxRun 只能是 6。
bug 2 · "数变化次数"不是"回返"的正确表达。 一个渐变序列同样能让变化次数很高；而 bug 1 又把这个数抬高，于是单向转变被抬过了 >=3 的闸门。

v1.28 的判据：折叠后看有没有回到已经出现过的状态

单向渐变   [a b c c c c c c] -> 折叠 [a b c]             rev=0    不触发
加载亮起   [a a b b b b b b] -> 折叠 [a b]               rev=0    不触发
真振荡     [a b a b a b a b] -> 折叠 [a b a b a b a b]   rev=12   触发

阈值：fill>=8 && distinct<=3 && revisits>=1。 一个单向转变在构造上就不满足它 —— 这正是 v1.26 / v1.27 都缺的那一条。

同时新增 shape=[...]：把窗口按状态编号打印，肉眼可读，不必再拿哈希去推：

#N ... shape=[0 1 2 2 2 2 2 2]   <- 单向，一眼是单向
#N ... shape=[0 0 1 1 1 1 1 1]   <- 亮起，一眼是单向
#N ... shape=[0 1 0 1 0 1 0 1]   <- 振荡

`shape` 是给下一轮的校准用的：判据第一次跑不能当证据读，但形状可以当校准读。

cpuD= 怎么读（这是关键）

cpuD ≈ 0进程在阻塞（IO / 锁 / 驱动等待）——没有线程在烧 CPU
cpuD ≈ 200有一个线程正烧满一个核
cpuD > 200多个线程在跑，或这一片超时了

GetProcessTimes 只读，不可能扰动进程。

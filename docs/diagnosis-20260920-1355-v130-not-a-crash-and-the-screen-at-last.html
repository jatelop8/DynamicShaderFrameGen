顺手记下一个测量伪影（别再当异常读）

presentAge=-4ms / -16ms / -12ms 是负值。 原因是 nowMs 在 watchdog 循环顶部取一次，而 SendMessageTimeoutA(..., 200ms) 排在写这一行之前 —— nowMs 相对 g_presentEnteredMs 最长可以过期 200 ms。 名字叫 age，参考点却是旧的。

4. 我 v1.29 加的四台仪器：两台按构造就不可能触发

v1.29 给 4x SNAPSHOT / 4x probe / FLIP COUNTER FROZEN 配的前提条件是：

const bool warm4x = frames > 200ull && lastPr > frames * 3ull;   // 累积比

这是累积比。而 lastPr 只有在 4x 活着的时候才会跑到 frames 前面，所以「累积比 > 3」等价于要求 「4x 已经活了整个会话的大部分时间」。本局末态 lastPr=906 / frames=705，测试要 lastPr > 2115 —— 它要的那 2115 次翻转，在这个 2 秒的窗口里根本不存在。

四个读数一个都没出现，四个零全是仪器，不是现象。
这正是我自己写下的 L42「仪器必须自证运行过」的第四次踩坑 —— 前三次是探针挂在永不执行的分支上，这一次是探针挂在一个被它要测的现象所否证的前置条件上。

L66（本轮新增）：一个仪器如果要求「我要测的那个现象已经成立」才启动， 那它就永远测不到那个现象。

修法有两处：把「4x 是活的」改回它本来该有的定义 —— 速率 （dFlips / dFrames >= 3 在最近 200 ms 的切片上；34 次入口/秒 ⇒ 切片内约 7 帧，取 3 是保守的，装载期比值是 1.00 所以不可能误触发）； 以及让 FLIP COUNTER FROZEN 去掉对 live4x 的依赖 —— 它要问的是「我方 Present 在跑而翻转计数没动」，而一个要求「4x 必须活着」的 前置条件，恰好会藏住「4x 被请求了但没到」这一种情况。

5. 第三条误报：0.9/255 的抖动不算「回来了」

v1.28 的回访判据（revisits >= 1）本局触发 4 次，窗口逐字：

shape=[0 0 1 1 1 1 2 1]     亮度 0.0 / 0.0 / 104.0 ×4 / 104.9 / 104.0

这是加载屏由黑转亮的一次单向渐变，加上一个比邻居亮 0.9/255 的样本。 revisits 数的是折叠序列里所有非相邻的相等对： 一次真实的 A,B,A,B,A,B,A,B 得 12，单个毛刺得 1。 所以门槛抬到 2 就能分开，且不动真正需要的灵敏度（实测对照，不是推理）。

★ 这是同一个探针的第三次误报（v1.26、v1.27、v1.28 各一次）， 而它一次真阳性都没有过。它读的是 colorOut —— 交给 DLSS-G 的 输入，所以从原理上看不见插帧之后的画面。它剩下的正当用途只有 「我方这一侧有没有动」。

6. 盲点有了准确的名字，而且比之前说的更大

读数它到底测什么
frames=我们自己的 Present 被进入了多少次
lastPr=我们自己的 swapchain 翻转了多少次
[PIXEL]我们交给 DLSS-G 的 D3D11 纹理（输入）的哈希
cpuD=我们整个进程的 CPU 时间
silent= / presentAge=我们自己函数调用之间的间隔

没有任何一个读屏幕。而且 lastPr 上涨连「面板动了」都证明不了： FLIP 模型下有翻转队列，Present 可以在任何东西扫出之前就返回。 ⇒ 「DXGI 报 137 翻转/秒」从来不是「画面在动」的证据 —— 这条我上一轮说得比实际强，纠正。

v1.30 因此加了屏幕探针

  • 在 watchdog 线程里每秒一次 GetDC(NULL) + StretchBlt 到 64×64 DIB，算哈希与平均亮度，与我们自己 colorOut 的哈希并排保存。 窗口按写序读（v1.28 在环形缓冲上犯过这个错）。
  • HALFTONE 是有意的：最近邻在 4K→64 的降采样里只采到 1/60 的像素， 可能整片漏掉真实变化。
  • 判据只有一条，也是这个工程里第一条关于屏幕而不是关于我们的判据： 
    窗口内 sDistinct <= 1 && pDistinct >= 3   ->   [SCREEN] STALE
  • 两条自证：捕获创建失败打 [SCREEN] ERROR；连续十次全黑打 [SCREEN] BLIND（独占全屏会让桌面捕获什么都看不到， 而沉默会被读成健康）。

★ 顺带排除一条假设 —— 不需要再跑一局： DX12SwapChain.cpp:206 / 241 里 CreateSwapChainForHwnd(commandQueue.get(), a_swapChainDesc.OutputWindow, ...) 用的是游戏自己的窗口。「FG swapchain 建在一个隐形窗口上、present 打到看不见的地方」 不成立。

7. 输入见证：换一个问法

本局 16 行 [CAM] PC 全是 kb=0（255 个 VK 全扫）， 而同一行的 dc=（鼠标位移/事件数）读到 2006/1、2155/1、2132/1。 ⇒ 鼠标到了，键盘没有。

但「255 个键此刻都没按下」和「用户什么都没做」仍然是两句不同的话， 而且 1 Hz 采样本身有 1 秒的洞。v1.30 加 GetLastInputInfo （ai=<距上次输入 ms>）：它问的是「这个会话里有没有任何输入」， 与是哪个键无关，而且返回时间戳而不是状态，1 Hz 够用。

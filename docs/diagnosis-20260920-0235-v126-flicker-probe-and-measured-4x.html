四、v1.26 改了两处 —— 都是仪器，不是功能

A · PixelProbeTick() 现在能测「振荡（闪烁）」

  • 采样块顺手算平均字节亮度 lum（沿原来的 FNV 循环累加；RowPitch 填充是稳定的， 只会把均值稀释一个固定量，造不出假摆动）。
  • 保留最近 8 个 (hash, lum)。判据：不同 hash 数 ≤ 3 且 亮度摆幅 > 40/255 ⇒ 打 [PIXEL] FLICKER，并附整个 8 窗口。样本行加 lum= seen=/{}/ swing=。
  • 这条判据不需要输入、不需要相机移动 —— 而依赖"玩家走路"的旧判据，自加入以来一次都没可能触发。

B · FPS 探针加一行「实测倍率」

  • [FrameGen] FLIPS per real frame = X.XX (DXGI lastPresentCount a -> b, our Present c -> d)， 每 2 s 输出一次。
  • 并给 FSR3 分支补上 GetLastPresentCount（v0.74 起只有 DLSS-G 分支记录它） —— FSR3 是唯一活过的 provider，这个不依赖运行时的读数在那儿原本是缺的。

五、两条否定（A≠B）

  1. first-chance 访问违例与本故障无关。本局 crash log 有 3 条 0xC0000005， faulting module = D:\ENB-EJ\Skyrim Special Edition\DINPUT8.dll（= Transfusion 自己）， rva=0x7B9D，读的是 …\NGX\models\dlssg\…\160_876232C.bin 的 MZ 头（Rax=0x5A4D） —— 它在扫 NGX 的 dlssg 模型 blob。
    但逐局计数是 3 / 0 / 3 / 0 / 3（00:31=3、00:58=0、01:30=3、01:56=0、02:25=3） ⇒ 有故障的局里也可能一条没有 ⇒ 划掉。
  2. "加载期武装 4x 有害"既没被推翻也没被坐实，但本局加载期 lastPr/frames 恒为 1.00， 说明那 30 秒里没有任何多余翻转。

六、修正：那 30 秒停顿不在我方 Present() 里面

上一轮我把 stage=d3d11 Wait 读成"我们的围栏在等"。这个读法是错的：

  • 那段里 frames（= ++frameCounter，写在 Present() 里、在任何调用之前） 从 1 不动 ⇒ 渲染线程 30 秒里一次都没再进过 Present()；
  • presentAge 也是陈旧的：它量 nowMs - g_presentEnteredMs，而那枚时间戳停在 02:24:29.309 没更新过 ⇒ 26 s 的 presentAge 是同一枚旧时间戳；
  • 所以 stage=d3d11 Wait 是上一帧结束时留下的名字，不是"当前所在调用"。

⇒ 只能得出：渲染线程卡在我们看不见的地方（引擎侧），看门狗没有能力给它命名。 以后看门狗里的 stage= 要降级读成"最后写下的那个名字"。

src/DX12SwapChain.cpp:719-722，v0.63 留下的原文：

才允许报卡死，未达标只记 silent（装载期的正常表现）。

⇒ 装载期 frames=1 + stage="d3d11 Wait" 是已知的正常现象， 而且当时就已经处理了（warm = frames >= 60）。

本轮第一次把它量化：dt min/avg/max=17.74/29.53/21426.80ms —— 不是「20 秒没进 Present」，是「有一帧真的跑了 21.4 秒」。

三、真正修掉的东西：两个「变化才打」的日志，值一次都没变

日志一局打了多少次它打印的值变了吗根因
Reflex cap check (v1.12) 4960 没有 —— 4822 次全是 159 flip fps … at 2x 两个 plain static 被两个线程读写
Reflex options applied 4896 没有 —— 全是 mode=1 frameLimitUs=6289 markers=true 同上 + memcmp 比多字结构

第二个更严重：它决定的是「要不要调用」，不只是「要不要打印」

static sl::ReflexOptions lastOpts{};
static bool lastValid = false;
if (!lastValid || std::memcmp(&lastOpts, &opts, sizeof(opts)) != 0) {
    slReflexSetOptions(opts);   // ← 每帧被调用
    ...
}

两个字宽的写不是原子的：一个线程写 lastCapFps 的同时另一个读 lastCapMult， 两边都「看到变化」⇒ 边沿检测器退化成每帧触发。 本插件 Present 路径两个 tid 都走（Transfusion 自己的 trace 也显示两个 tid 到达姊妹调用）。

修法：把签名打包成一个 std::atomic 字，用 exchange 比较 —— 一次真边沿只有一个线程能拿到旧值。

这不是改变设计，是恢复设计：v0.35 的原注释写的就是「选项变化才 slReflexSetOptions （缓存比较，CS 同款）」。缓存比较从未生效过。

本轮最省时间的一条推理：

一行日志如果把自己的值一起打出来，那么当它带着同样的值重复时， 它就自我否证了 —— 坏的是判据，不是值。

下次看到「变化才打」的日志在刷屏，第一件事是把它打印的值读出来， 而不是去查它测的东西。（账本 L60）

四、两个测不到东西的仪器，换掉了

4.1 输入见证只能证明「不是那八个键」

原来的掩码是 W A S D Space Shift LMB RMB。16 局连续打出 os=0x0， 每一局都被读成「用户没碰过键盘」。

但那个掩码只能证明否定命题「不是那八个键」。一个觉得画面卡死的玩家， 最先按的是 ESC 或 Alt+F4 —— 两个都不在掩码里。

于是「不是这八个」被静默升级成「完全没有输入」，而整个输入见证的结论就架在这个越界推论上。

修法：每秒扫全 vk 1..255，kb= 打印当前按住的键数， 并在任何键变化时打一条 [INPUT] vk 0x.. -> 0x.. (N held, fg=1)。

已写明的局限：1 Hz 采样，两次采样之间按一下就松开的键会被漏掉； 协议要求的「按住 W 十秒」漏不掉。

4.2 屏幕上到底有没有新帧 —— 从来没有仪器回答过

frames= 数的是我们的 Present 进入次数，lastPr= 数的是我们的 swapchain 翻转次数 —— 两个都在我们这一侧。 本局两者都在涨（2.86 秒里 98 次进入、392 次翻转 = 137 翻转/秒 = 正好 4x）， 而你说画面是卡的。这个矛盾才是本轮真正的待办。

新增两条：

  • [XRAY] 4x SNAPSHOT t=0 —— 倍数落到 4x 的那一 tick（判据 frames>200 && lastPr>frames*3，登录界面 lastPr≈2×frames 达不到， 不会误触），随后 3 秒内每 5 tick 一条 4x probe，带实测面板翻转率。
  • [XRAY] FLIP COUNTER FROZEN for N ticks —— lastPr 连续 5 tick 不涨 而 frames 仍在涨。

为什么必须在这一秒级窗口里打：最近 6 局每一局都在世界时间 6 秒内结束， 所以「一分钟才打一次」的速率等于从未被看到过。

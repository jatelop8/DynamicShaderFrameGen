三、头号嫌疑：INI 自己写明了机制（v1.01 引入）

DynamicShaderFrameGen.ini 第 218 行的原文：

; 1 = NR runs first on the real frame and DLSS-G then interpolates the
;     neural-rendered result. (...) (NR writes swapChainBufferWrapped,
;     which is what EvaluateDLSSG reads, with the D3D11->D3D12 fence between them).
; Start at 0 if the picture flickers (...)
NRAllowWithFrameGen=1

「NR 写 swapChainBufferWrapped，而 EvaluateDLSSG 读的就是它」 —— 如果 NR 的写入没有落地（fence / 互操作失败），DLSS-G 每个真实帧读到的都是同一张陈旧缓冲： 画面完全定死，而 Present 一直成功、presentAge 一直正常。这正是观测到的形状。

而 NRAllowWithFrameGen 是 v1.01 才有的串联 —— 它之前任何版本都没有这条路，与「冻结从 MFG 这条支线开始」完全吻合。

七、我自己这次的三处错（都在游戏之前被拦住）

  • 引擎侧按键见证拖垮链接：调 GetKeyboard() 会让链接器从 CommonLibSSE.lib 里拖出 BSWin32KeyboardDevice.cpp.obj 与 BSKeyboardDevice.cpp.obj，这两个编译单元引用了 14 个 RE::BSInputDevice 虚函数而预编译库里没有定义 ⇒ 14 个 LNK2001。整个见证删掉了。
  • 我把 L(...) 的闭合括号写成了字符串：手写补丁时写成 ")"， 于是 ast.parse 报「第 52 行括号未闭合」，而肉眼看那一行完全正常。 ⇒ 新增强制步骤：跑任何补丁脚本前先 ast.parse 它自己。
  • L35：v1.18b「修」了一个不存在的 bug。我当时按「AcceptCameraSnapshot 每秒跑 400 次」推断， 把 s_plrStep 从 = 改成 +=；但那段见证在每秒执行一次的块里 （[CAM] PC 每秒恰好一行、read=425 是「这一秒读了几次」），两者在此等价。 ⇒ 给一个数值标量纲前，先确认它在哪个块里，而不是它在哪个函数里。

3. 这次到底改了什么（一句话 + 一个式子）

Streamline.cpp 里计算重投影矩阵时，取逆用的相机和「上一帧」用的相机不是同一台： 取逆用的是引擎那份没有平移的 ViewProj，乘的却是我们自己重建的、含相机位置的矩阵。 两个不同构的矩阵相乘，平移项无法抵消： 

inv( P @ [R|0] )  @  ( P @ [R | -R@eye] )
  = [R^T|0] @ [R | -R@eye]
  = [ I | -eye ]        ← 旋转精确等于单位阵，平移是整个相机位置
                           eye = (-243.05, -415.31, 118.56)  ⇒ 平移量级 ~495

所以 `det3()`（只读 3×3）一直报 1.000000、 看起来完全健康，而 DLSS-G 收到的是一句谎话： 「相机没转，但平移了半个世界」。它据此生成插值帧 → 画面来回。

修法（单点）：取逆改用与「上一帧」同源的矩阵 —— camCurOk ? camCurVP : curForReproj。 相机静止时两边同源，结果精确等于单位矩阵。

8. 本轮新增：两个「看起来是真」的假读数

不影响这次要看的三个判据，只是记下来 —— 因为我差点把它们当成事实写进结论。

读数为什么是假的
jitter=(0.0000,0.0000) 全工程源码里 jitterX/jitterY 是 1 处声明 + 2 处读取 + 0 处写入 —— 唯一写者 OnMainUpdateJitter 在 v0.50 被删了。所以这 8 条心跳全 0 是必然，零信息量。
（上一轮我就是拿同样的坏仪表 move=0.0000 推出「相机原地不动」，写废了一整章。）
mvecScale=(1.000,1.000) 被 INI 的 MvecScaleOverride=1.00 钉死，运动中也恒为 1。

顺带翻出一个更大的事（但这次不要动它）： 代码注释说「超分已拔掉」，实际 RenderResolutionScale=0.44 —— 日志 Render scale 0.440 -> 1689x950 render / 3840x2160 output。 超分一直是活的，而我们把 jitterOffset 喂成 0。 那条注释是 v0.50 写的，此后配置改了、注释没改。
⇒ 这是一个待查方向，不是本次的修复。判断它有没有害，还需要一行新日志 （把 CameraProj 与 CameraProjUnjittered 逐元素 diff）。 先让 v1.07c 单独跑完 —— 一次只动一个变量。

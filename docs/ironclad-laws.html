「每次你看完日志改完要自我检查两遍 再给我 不要每次骗我 这个是铁律 记住 每次照做」

「骗」的判据不是"有没有撒谎"，而是"手里有没有证据"。 未经证实的断言，在用户那里与欺骗等价——他要花时间去跑、去试、去发现是空的。 没有证据只能写「未证」；不确定必须说「不确定」。先给结论、后补验证 = 骗。

  2. 逆操作还原 → 逐字节相同（纯增量证明）
  3. 行尾 CRLF/LF 计数 + stray = 0
  4. 构建通过（便宜，但不是唯一验证器）

第二遍 · 脑子我说的结论真的站得住吗

  1. ★ 反向假设：若结论是反的，日志长什么样？我看到的能否排除它？
  2. 这个量有没有写者 / 配置有没有 override / 注释是否过期
  3. 这条代码路径真的会被走到吗
  4. 「改 A 为 B」前证明 A ≠ B
  5. 同时发生 ≠ 因果（分不开就写「未证」）
  6. 空集 / 异常值会不会被静默当成「健康」
  7. 用户会不会因此白跑一趟

交付时逐条列出两遍的结果，不写"我已检查过"——用户要的是能据此行动的信息。
